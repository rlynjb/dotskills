# Context quality and requirements

## Required context

Establish the target repository, accessible revision or workspace, and read access to its tree and essential files. If the target is ambiguous or inaccessible, ask for the smallest missing input rather than inventing an onboarding guide.

## Supporting evidence

Inspect applicable repository instructions, README/docs, manifests and lockfiles, configuration, entry points, representative implementation files, tests, and CI/deployment definitions. Map all major first-party areas at a useful level without reading every file indiscriminately. Treat documentation as claims to compare against implementation; flag conflicts.

## Scope and completion

Preserve the master's staged teaching workflow and whole-repository scope. Representative flows illustrate the repo rather than replacing its architecture map. State the revision, areas inspected and omitted, unknowns, and access limits. Keep claims grounded in files and symbols, use verified line references only, and distinguish commands inspected, executed, and proposed. Deliver the final learning summary and practical onboarding path after the applicable stages; label early stopping or incomplete coverage partial. Keep exercises read-only.
